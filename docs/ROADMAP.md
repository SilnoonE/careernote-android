# 후속 개발·검증 로드맵

이 목록은 계획입니다. 체크되지 않은 항목을 완료 기능으로 해석하지 마세요.

## 먼저: 데이터 신뢰성

- [ ] 지원 버전별 Room 마이그레이션 회귀 테스트
- [ ] 정상·손상 백업과 실패 주입 테스트
- [ ] ZIP 경로·크기·항목 제한 검증
- [ ] DB·설정·초안·첨부의 함께 복원 및 롤백 검증
- [ ] 초안 동시성 및 저장 순서 테스트
- [ ] 제출 전후 취소·합격 이력 통계 테스트

## 다음: 사용자 흐름 완성

- [ ] 등록→수정→복제→삭제→재조회 시나리오
- [ ] 문서별 임시저장과 이어쓰기 검증
- [ ] 원본 변경·삭제 이후 제출본 및 첨부 열람
- [ ] 알림 권한·재부팅·변경·삭제·클릭 이동 검증
- [ ] 다국어·큰 글꼴·다크 모드·키보드 표시 검증
- [ ] 공개용 광고 자리표시자가 화면 흐름을 유지하는지 확인

## 이후: 기록 활용도 높이기

- [ ] 기업별 제출 서류와 면접 회고를 한 흐름으로 연결
- [ ] 자소서 문항별 작성과 글자 수 관리
- [ ] 프로젝트의 상황·역할·행동·성과를 서류 작성에 재사용
- [ ] 오늘 할 일·작성 중 초안·다음 일정 중심 홈 구성
- [ ] 기간·서류 버전별 리포트와 표본 수 설명

## 변경을 남기는 방법

1. 재현 조건과 기대 동작을 이슈 또는 문서에 작성합니다.
2. 하나의 문제를 해결하는 변경을 커밋합니다.
3. 테스트 명령, 결과, 기기 확인 여부를 기록합니다.
4. 남은 제약과 호환성 영향을 설명합니다.
5. 공개 전 비밀정보와 운영 설정의 포함 여부를 검사합니다.

권장 커밋 예: `fix: preserve interview records when toggling favorites`.
과거 개발 과정을 보여주기 위해 존재하지 않는 커밋을 소급 생성하지 않습니다.
