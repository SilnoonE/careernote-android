# 개발·개선 기록

이 문서는 2026-09-16~17에 진행한 개발 피드백과 소스 검토의 회고입니다.
당시 버전의 Git 커밋이나 재현 가능한 변경 diff가 아니며, 각 단계의 검토 결과를 현재 코드의 결함으로 단정하지 않습니다.

## 1. 초기 점검

지원 관리와 8종 커리어 기록을 확인했습니다. 기록 입력·조회 중심 흐름을 기업 지원, 제출 서류, 면접, 회고로 연결하는 방향을 정했습니다.
초기에는 복원 전 원본 삭제, 파괴적 마이그레이션, 상태 enum 순서에 의존한 통계, 수정·삭제 UI와 작성 보존의 부족을 지적했습니다.

## 2. 고도화 요구 구체화

데이터 보존을 먼저 확보하고, 통계·날짜, 기록 편집·초안, 지원 검색, 서류 연결, 면접·알림 순으로 개선하는 요구사항을 작성했습니다.
운영 앱의 광고와 하단 탭은 유지하는 것이 일관된 요구였습니다.

## 3. 구현 보고와 코드의 대조

여러 차례의 검토에서 모델·DAO만 추가되고 화면에서 사용할 수 없는 기능을 구분했습니다.
즐겨찾기에 REPLACE를 사용하면 연결 이력이 삭제될 수 있는 문제를 찾아 UPDATE 기반으로 개선된 것을 확인했습니다.
검색·필터 UI, 기록 편집, 전체 내용 스냅샷, 면접 날짜·시간 선택이 단계적으로 추가됐습니다.

## 4. 실패 경로를 중심으로 재검토

백업의 일관성, 롤백 사본 보존, ZIP 경로 검증, DataStore 하위 파일 복사, 초안 로딩·동시 저장, 취소 전후 통계, 재부팅 후 알림 이동을 주요 검증 항목으로 만들었습니다.
빌드 성공과 데이터 안전성 검증은 별개라는 원칙을 적용했습니다.

## 5. 공개용 스냅샷 준비

2026-09-17 원본 구조 공개를 결정했습니다. 광고·비밀정보는 제외하고 코드와 개발 과정 문서를 별도 사본에 준비했습니다.
이후 수정은 실제 변경 단위의 커밋과 테스트 결과로 추적하는 것을 권장합니다.

## 6. 2026-09-23 화면 안정성과 사용 흐름 개선

기존 공개 스냅샷을 지우지 않고 원본 앱의 최신 변경분을 추가했습니다. 공개 정책에 따라 운영 광고 구현과 실제 광고 ID는 계속 제외했으며, 그 외 앱 구조와 기능 코드는 가능한 한 그대로 보존했습니다.

### 상단바와 화면 이동

- `MainContainer`의 상단바가 시스템 상태바 영역을 자연스럽게 처리하도록 기본 `TopAppBar` 인셋을 사용했습니다.
- 커리어 목록, 추가·수정, 상세, 지원 상세 화면의 제목과 뒤로가기 버튼 위치를 맞췄습니다.
- 커리어 목록 경로에 `onBack` 동작을 다시 연결해 상단 뒤로가기 버튼으로 이전 화면에 돌아갈 수 있게 했습니다.

### 지원 관리 화면

- 지원 상태를 `전체`, `진행 중`, `예정`, `완료` 그룹으로 묶는 필터 모델과 화면 상태를 추가했습니다.
- 지원 카드와 통계 카드의 정보 계층을 정리하고, 상세 화면의 회사·직무·상태·일정·첨부 정보 배치를 개선했습니다.
- 지원 상세의 상태 변경, 면접 일정, 공고 URL, 수정·삭제 동작은 기존 ViewModel 흐름을 유지했습니다.

### 커리어 팁 화면

- 홈 미리보기에서 Markdown 제목·목록 기호가 그대로 노출되지 않도록 첫 유효 문장을 정리해 표시합니다.
- 카테고리 카드의 색, 아이콘, 배경 장식과 상세 화면의 헤더·카드 간격을 조정했습니다.
- 취업 가이드 카드의 장식 위치와 크기를 고정해 화면 폭에 따른 어긋남을 줄였습니다.

### 테마

- 설정 선택지를 기본 모드와 다크 모드 두 가지로 단순화하고, 최초 실행 기본값을 밝은 테마로 바꿨습니다.
- 다크 테마의 배경, 카드, 보조 텍스트, 경계선 색을 조정해 대비를 낮추고 읽기 편하게 만들었습니다.
- 앱에서 고른 다크 테마가 시스템 테마보다 우선하도록 적용 경로를 정리했습니다.

### 공개 사본 검증

JDK 21, Android SDK 36 환경에서 `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug`를 함께 실행했습니다. 빌드와 4개 단위 테스트는 성공했고 Lint도 오류 없이 완료됐습니다. 경고와 아직 필요한 기기 검증은 `VERIFICATION.md`에 남겼습니다.

## 배운 점

- 버튼·필드·클래스의 존재만으로 기능이 완료된 것은 아닙니다.
- 저장·복원 기능은 성공 경로보다 실패 후 원본을 지키는 동작이 중요합니다.
- 기존 데이터의 의미를 보존하는 마이그레이션과 통계 정의가 필요합니다.
- 변경 기록에는 실제로 검증한 것과 아직 확인하지 못한 것을 구분해야 합니다.
